为当前变更创建 Git 提交，默认使用简洁的中文 Conventional Commits 标题；项目已有规范时优先遵循项目规范。

## 格式

`<type>(<scope>): <summary>`

- `type` 必填：新功能使用 `feat`，缺陷修复使用 `fix`；其他常见类型包括 `docs`、`refactor`、`chore`、`test`、`perf`。
- `scope` 可选：用括号中的简短名词表示影响范围，例如 `api`、`parser`、`ui`。
- `summary` 必填：使用祈使语气，保持简短，不超过 72 个字符，末尾不加句号。

## 注意事项

- 正文可选；需要时在标题后空一行，再写简短段落。
- 不自行添加破坏性变更标记、签署或其他 trailer；如果项目指令要求，则按项目指令执行。
- 只提交，不推送。
- 不确定某个文件是否应纳入提交时，先询问用户。
- 调用方提供的参数视为额外提交要求：
  - 自由文本会影响 `scope`、`summary` 和正文。
  - 文件路径或 glob 会限制提交范围；除非用户明确要求，否则只暂存并提交指定文件。
  - 参数同时包含文件和说明时，两者都要遵守。

## 步骤

1. 从请求中识别指定文件、glob 和附加说明。
2. 查看 `git status` 与 `git diff`，理解当前变更；若指定了文件，只检查对应范围。
3. 可选：运行 `git log -n 50 --pretty=format:%s`，了解项目常用 `scope`。
4. 如有来源不明或范围不清的额外文件，提交前询问用户。
5. 只暂存目标文件；未指定文件时才考虑当前任务的全部相关变更。
6. 运行 `git commit -m "<subject>"`，需要正文时再增加一个 `-m "<body>"`。
