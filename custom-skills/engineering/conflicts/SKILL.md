# Git 冲突处理

## 怎么做

1. 读取 `git status`，确认正在进行哪种 Git 操作、哪些文件冲突，以及冲突前两边分别有哪些改动。保留与本任务无关的用户修改。
2. 对每个冲突块查看相关规格、测试和提交，判断两边内容能否合并、应该保留哪一边，还是两边想法不同而需要用户选择。
3. 只有用户要求解决且选择清楚时才编辑文件。删除冲突标记后，运行最相关的测试和静态检查。
4. 报告每个文件保留了什么、为什么这样选、还有哪些问题没有决定，以及检查结果。

## 限制

解决冲突本身不等于授权执行 `--continue`、`--abort`、暂存、提交或推送；用户明确要求其中某项时，先确认当前 Git 操作和目标，再执行。用户没有给出足够信息时，停在冲突文件已分析的状态并提出具体问题；不要覆盖无法恢复的数据。
