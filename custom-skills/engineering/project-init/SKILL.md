# 项目初始化

## 目标

让 Agent 能从仓库事实中找到必要的工程规则、验证方法和工作记录。只补实际缺口；重复运行不改写已有正确内容，不复制上级或全局规则，不预建空架子。初始化 Agent 说明不等于搭建业务工程、安装 Skill 或开始执行任务。

## 怎么做

1. 从请求或当前目录确定目标项目，查看工作区状态、适用的 Agent 说明、主要目录、构建测试配置和持续集成文件。检查已有任务记录、`docs/agents/` 及相关 Skill 的读写要求。只读判断实际写法所需的材料；空项目不编造技术栈或命令。
2. 按实际缺口选择文件：
   - 项目根 `AGENTS.md` 保存项目用途、关键目录、已有开发和验证命令、项目特有约束及阅读入口。仅适用于子目录的规则放在对应目录；检查已有 `AGENTS.override.md`，避免新增说明被覆盖。
   - 只有用户要求支持 Claude 或项目已有该入口时，才处理 `CLAUDE.md`。沿用有效引用方式，正文只维护一份；不为了文件名一致重写已有内容。
   - 用户要求接入任务工作方式，或项目已有任务配置需要整理时，读取 [任务配置与迁移](references/task-workflow.md)。沿用实际任务系统，不根据 Git remote 推定使用外部 Issues，也不为普通初始化强加任务流程。
   - 已确认有本项目反复使用且容易混淆的领域词汇时，才维护 `CONTEXT.md`，不收录类名、配置键或内部处理阶段；已作出需要解释取舍的长期决定时，才写 ADR。简单项目直接在 `AGENTS.md` 指向现有资料；阅读规则复杂时才写 `docs/agents/domain.md`，说明何时读取相关术语与 ADR、沿用已有术语并明确报告 ADR 冲突；资料不存在时继续，不建议预建。不因 monorepo 自动划分领域或创建 `CONTEXT-MAP.md`。
3. 合并仍有效的内容并修复引用。在 `AGENTS.md` 写明处理哪类工作时读取哪些文档，不假设普通 Markdown 会自动加载。沿用已有 `doc/agents/`、`issue-tracker.md`、`spec.md` 等路径；没有约定时使用 `docs/agents/`。规则冲突或迁移含义不明时保留相关原文，报告具体待决定项，继续处理不受影响的部分。
4. 用户只要求检查或先给方案时，报告发现、建议文件和重要选择，不修改文件。已授权初始化时直接完成范围内的本地改动；只有影响任务系统选择、数据保留或权限的未决问题才询问。
5. 查看 diff，检查引用和字段定义一致性，并运行相关现有文档或配置检查。区分从配置确认的命令与实际执行通过的命令。确认没有重复规则、空占位内容或范围外改动；说明创建、更新、迁移及未解决的内容。

## 限制

- 不创建空目录、示例任务或占位文档；模板用于有真实任务时，不在初始化时生成任务。
- 不修改 HOME 或目标项目之外的设置，不安装依赖，不改变持续集成、远程系统或生产环境。
- 初始化请求不授予创建分支、暂存、提交、推送或启用 Skill 的权限；用户明确要求时才执行。
