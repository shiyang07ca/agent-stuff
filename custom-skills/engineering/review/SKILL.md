# 代码审查

## 怎么做

1. 先确认审查哪些改动、与哪个版本比较，以及哪些文件不在范围内。读取相关需求、项目规则和已有测试结果；缺少的信息直接说明。
2. 检查改动是否符合需求，代码是否容易读和修改，是否引入安全、数据、性能或运行问题。重点看错误处理、权限、兼容性、资源释放、并发和用户能看到的结果。
3. 对新增模块、抽象和依赖检查是否真的有使用方，以及仓库现有代码、标准库、平台功能或现有依赖能否替代。不能只看行数，也不能为了简化而删掉必要的输入检查、防止数据丢失的处理、安全措施、无障碍要求或测试。
4. 每个问题写清文件和行、会造成什么影响、根据什么判断、严重程度（`P0` 至 `P3`）和建议改法。把真实缺陷、尚未确认的风险和个人偏好分开，不要把风格偏好写成阻止合并的问题。
5. 如果改动新增了测试，检查它是否覆盖用户或调用方能看到的行为，是否只是锁定措辞、文件清单或私有实现。运行最相关的最新命令；只看代码不能确认时，实际运行一次，没有运行的检查明确写成未验证。

## 限制

审查默认只读，不直接修改文件、任务状态、评论、合并结果或提交。只有用户要求时才实施修复；不要求调用其他 Skill 或后台 Agent。
