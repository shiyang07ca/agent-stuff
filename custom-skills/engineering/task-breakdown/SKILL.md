# 任务拆分

## 怎么做

1. 读取目标项目的任务配置、已有 PRD（默认 `.scratch/<feature>/PRD.md`）、相关 ADR 和现有任务。规格里还有会阻止实现的问题时，把任务标为等待信息，不要假装已经可以开工。
2. 先列出任务之间的依赖，再决定顺序。每项任务都应交付一个能单独检查的结果；涉及界面、接口和数据时，尽量让一项任务完成一条真实使用路径，不要先把所有界面、所有接口和所有测试各拆成一批。
3. 每个任务写清要做什么、不做什么、怎样验收、怎样检查，以及 `Status:`、`Progress:` 和 `Blocked by:`。任务正文用中文，固定字段保持原样。
4. 大范围重构要说明怎样先兼容旧行为、迁移调用方、最后删除旧实现，以及失败后怎样恢复。无法安全拆分时，列出还需要决定的问题，不要生成一长串看似独立的任务。
5. 只有拆分方式会明显影响并行工作、风险或工作量时才询问用户；其他情况选择最小且便于审查的任务，并说明重要假设。

## 输出和限制

沿用目标项目的任务位置和字段约定；没有其他约定时，默认写入 `.scratch/<feature>/tasks/<NN>-<slug>.md`，沿用已有编号，不覆盖未完成任务。信息完整时使用 `Status: ready-for-agent`；缺少必要信息时使用 `Status: needs-info`；新任务设为 `Progress: pending`，依赖与满足条件写入 `Blocked by:`，无依赖写 `无`。字段定义读取目标项目的状态说明（默认 `docs/agents/triage-labels.md`）；已有不同状态方案时按其映射，不擅自迁移。

每项任务都要有完成条件和至少一种检查方法。“实现功能”本身不算完成条件。任务拆分过程只设置新任务的初始状态，不领取、关闭或删除任务；后续工作实际开始或完成时可以更新本地任务状态，并在答复中说明。没有用户授权时，不向外部任务系统发布内容或修改外部任务。
