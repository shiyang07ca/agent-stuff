# 任务整理

## 怎么做

1. 读取目标项目的任务配置、目标任务、相关 PRD、代码和已有结论，确认 `Status:`、`Progress:` 和 `Blocked by:`。先检查进度，避免把已完成、延后或取消的任务重新排队；缺少进度时读历史记录，不默认为未开始。
2. 检查目标、完成条件和必要信息是否清楚，并确认影响范围、重复任务、已有实现或不处理的理由。任务描述的是缺陷时，检查是否已有重现步骤；找不到的信息写成未确认。
3. 建议优先级、下一步、需要补充的信息和对应状态，并说明建议根据哪些文件、日志、链接或运行结果得出。状态使用目标项目状态说明（默认 `docs/agents/triage-labels.md`）规定的值，已有其他方案时按其映射。默认分诊值为：信息不足用 `needs-info`，信息完整且 Agent 可以处理用 `ready-for-agent`，必须由人处理用 `ready-for-human`，决定不处理用 `wontfix`。
4. 结论明确时更新本地任务的分诊状态和阻塞说明；不领取任务，不因信息已充分就标记完成。只有明确决定延后或取消时同步相应进度。每次修改追加带日期的事实和决定，保留历史；在答复中说明修改了什么。没有足够依据时保留原状态。

## 限制

对外部系统默认只读，不自行评论、关闭、删除、转派或修改。没有文件、日志、链接或运行结果支持的内容就写“未确认”，不要为了让任务看起来完整而补写。涉及权限、数据或生产环境时，明确指出需要谁决定什么。
