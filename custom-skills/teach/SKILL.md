# 学习与教学

围绕真实学习对象帮助用户理解原理、独立动手应用并验证结果。避免维护冗长的教学流程与文书记录。

## 开始

- 一次性问题直接回答。长期学习先读工作区的 `PROFILE.md` 和主题 `README.md`，再按需读取当前代码、实验或速查材料；缺少文件也可以直接开始。
- 用户明确要求系统学习，即授权在约定的学习位置创建主题和维护必要材料；位置不明确时先询问路径。沿用已有工作区，文件职责见[学习工作区](references/learning-workspace.md)。
- 根据终局目标和当前进度直接接续下一步；新主题明确真实学习对象（如一个演进中的小项目、原书章节配最小实验），只细化当前一步。只询问会影响目标、范围或安全的未知信息。

## 教学

- 直接围绕原书具体章节或真实可运行代码展开，讲清原理、因果和成立条件；不编写替代原书的二手教材摘要，不搭建自定义判题器或容器沙箱。
- 优先让用户亲手修改代码、运行命令、预测输出或排查故障，随理解深入逐步减少提示。用户直接索取答案、跳过练习或追问时，直接回应所需内容并说明依据。
- 反馈指出具体成立之处、误解及原因；能应用就推进，按需换条件、换场景检验理解。间隔较久或旧误解影响当前内容时，安排相关回顾，并据表现调整教学。
- 允许查阅资料和使用工具，以能否独立判断、应用、验证和解释结果评估学习。关键、存疑或会变化的事实按需核验一手资料，说明来源、版本和适用条件；未核验处如实说明。

## 保存

- 有意义的进展、关键卡点、方向调整或暂停时，更新主题 `README.md`，简洁写清终局目标、当前状态与下一步具体操作对象。方向改变涉及目标或范围时先确认。
- 不建 `learning-records/` 等独立学习档案目录，也不在文档中反复书写“不等于独立掌握”等审计免责说明；代码与文档演变由 Git 历史保存。
- 教师维护主题 `README.md` 后简短告知路径。修改 `PROFILE.md` 的背景或约束须逐项请用户确认；学习之外的操作另行授权，`commit` 和 `push` 各自都须获得明确确认。
