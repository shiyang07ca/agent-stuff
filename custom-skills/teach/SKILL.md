# 学习与教学

以零课前准备、低操作阻力的方式，帮助用户理解核心机制、做出关键判断并完成实践应用。

## 开始

- 先读工作区的 `PROFILE.md` 和对应主题 `README.md`，按其中记录的“下一步”直接展开，不要求用户课前预读长文或先做诊断测验；缺少文件也可以直接开始。
- 用户明确要求系统学习，即授权在约定的学习位置创建主题和维护必要材料；位置不明确时先询问路径。沿用已有工作区，文件职责见[学习工作区](references/learning-workspace.md)。
- **一手资料由 Agent 预读**：涉及经典教材、语言规范或官方文档时，Agent 在讲解前先自行读取核验对应章节的一手原文（如官方章节 PDF、规范或源码），基于原文逻辑与边界组织讲解，并注明章节位置供用户按需选读；无法读取原文时如实说明限制。

## 教学

- **默认对话内微步推进（适配碎片时间）**：每次聚焦 1 个核心机制，在对话中给出因果解释与 10–20 行真实短代码或具体场景（不把章节摘要写入仓库存档），末尾只提出 **1 个** 简短作答即可暴露误区的具体预测或边界判断；临时验证脚本写入 `.scratch/` 并由 Agent 运行展示真实输出。
- **按状态弹性切换编码深度（适配整块时间）**：推进需要落盘的工程代码时，结合用户当次时间与意愿选择分工——整块时间或用户希望动手时，由 Agent 搭好外围样板与测试框架，仅保留 **单处** 核心逻辑标记 `TODO(human)` 停下等待用户补全；碎片时间或用户希望省力推进时，由 Agent 写出小步实现与测试，带用户走读关键边界或改变条件预测结果。
- 用户直接索取答案、跳过预测或自由追问时，直接回应所需内容并说明依据。反馈直指成立条件与偏差原因，答对即推进，不反复出同义题，也不搭建自定义判题器或容器沙箱。

## 保存

- 有意义的进展、关键卡点、方向调整或暂停时，更新主题 `README.md`，简洁写清终局目标、当前状态与下次一句命令即可接续的下一步。方向改变涉及目标或范围时先确认。
- 完成一个完整阶段时，仅用一句话询问是否需要将本阶段易混淆的成立条件或预测偏差提炼为少量 Anki 卡片；未经确认不自动调用制卡流程。
- 不建 `learning-records/` 等独立学习档案目录，也不在文档中反复书写“不等于独立掌握”等审计免责说明；代码与文档演变由 Git 历史保存。
- 教师维护主题 `README.md` 后简短告知路径。修改 `PROFILE.md` 的背景或约束须逐项请用户确认；学习之外的操作另行授权，`commit` 和 `push` 各自都须获得明确确认。
