# 学习工作区

长期学习使用轻量工作区跨会话接续。用户明确要求系统学习后，在约定位置创建主题入口和当前直接使用的代码或实验；一次性问题直接在对话中处理。

## 文件职责

- 根 `README.md`：主题索引，链接各主题入口。
- 根 `PROFILE.md`：跨主题的稳定背景与教学约束。新增或修改的内容逐项取得用户确认；当次要求和主题目标优先。
- 主题 `README.md`：控制在精简篇幅内，集中保存终局目标、主要阶段、当前卡点及下一步具体操作。续学从这里开始。
- 学习对象：直接在主题目录下维护演进中的工程代码或确实需要反复查阅的单页 `reference/` 速查表；一次性验证实验写入 `.scratch/`，避免污染主题目录。

只创建当前真正使用的文件。不预制课件目录，不编写二手教材摘要，不搭建自定义判题沙箱，不建 `learning-records/` 等独立学习档案目录。

## 维护与权限

主题 `README.md` 只保存影响下次继续的事实（做到哪一步、暴露了什么具体问题、下一步改哪个文件或读哪一章），解决后的旧卡点直接更新，历史变化交由 Git 保存。不在文档中堆砌掌握度免责话术。

教师可以维护已授权学习范围内的主题入口和必要材料，更新后简短告知。修改个人背景与约束逐项确认；学习之外的代码、配置、生产数据和外部操作另行授权。`commit` 和 `push` 分别需要明确确认。

## 主题 README 示例

```markdown
# Go

## 目标

从零迭代交付一个使用 PostgreSQL 持久化并支持优雅退出的微型后端服务，在工程演进中掌握类型、指针、错误处理与并发控制。

## 演进阶段

1. 内存存储与表驱动测试（当前阶段）
2. `net/http` JSON 接口与输入校验
3. PostgreSQL 查询与事务边界
4. `context` 取消与 `SIGTERM` 优雅关闭

## 当前与下一步

- 当前：已完成内存存储结构定义与新增接口，对切片扩容后底层数组是否共享仍有疑问。
- 下一步：在 `store_test.go` 编写扩容前后的修改对比测试并运行 `go test -v ./...`。
```
