# 学习工作区

长期学习使用一个可跨会话接续的工作区。用户明确要求系统学习后，在约定位置创建主题和当前需要的材料；位置不明确时先询问路径。沿用已有结构，一次性问题可直接在对话中处理。

## 文件职责

- 根 `README.md`：主题索引，链接各主题入口。
- 根 `PROFILE.md`：跨主题的稳定背景与个人偏好，如工程经验、互动方式和学习节奏。背景帮助选择讲解起点，实际表现支持能力判断。新增或修改的内容逐项取得用户确认；当次要求和主题目标优先。
- 主题 `README.md`：统一保存目标、能力路线、当前进展、下一步及必要的工程入口。续学从这里开始，链接当前相关材料。
- `exercises/`：按需保存实际练习、代码和检查。
- `learning-records/`：按需保存影响后续教学的重要详细证据，包括实际表现、帮助程度、误解与纠正、适用边界和相关产物。
- `reference/`：按需保存会重复查阅的资料、命令、公式或步骤，注明必要来源和适用条件。

只创建当前需要的文件。对话用于即时讲解，练习用于实际应用；图表、演示等材料在确实有助理解或复用时采用。已有工作区按实际职责读取和更新，不为格式统一另建重复文件。

## 维护与权限

主题 `README.md` 保存当前情况，Git 历史保存文件变化；重要表现需要具体上下文时，在 `learning-records/` 中保留日期、用户做了什么、得到哪些帮助、结果支持什么判断及尚未验证什么。链接已有代码和检查结果即可，不必复制对话。

教师可以维护已授权学习范围内的主题入口和必要材料，更新后简短告知。教师完成的示范或检查明确记为教师行为，用户自述与可检查结果分别说明。一次正确或测试通过只支持相应条件下的判断。

修改个人背景与偏好逐项确认；学习之外的代码、配置、生产数据和外部操作另行授权。`commit` 和 `push` 分别需要明确确认，维护学习记录不自动授权这些动作。

## 主题 README 示例

以下展示 Bash 主题的最小入口。实际使用时按已有证据写清帮助程度和边界，详细证据链接到对应记录。

```markdown
# Bash

## 目标

能够安全阅读、修改和验证 Bash 脚本，解释执行结果，并判断脚本的适用条件和风险。

## 能力路线

- 理解命令执行和展开，判断参数如何传递。
- 理解管道和退出状态，验证数据流与执行结果。
- 组织脚本，明确输入、输出和职责。
- 处理失败，验证错误路径与清理行为。
- 管理进程，判断后台任务的等待、信号和清理范围。

## 当前进展

日志分析和后台汇总已实践；具体独立程度和提示情况以已有学习记录为准。直接子进程的 TERM 清理待实践，目前尚无用户独立完成该项操作的证据。

## 下一步

在 managed-child-cleanup 练习中实践直接子进程的 TERM 清理，观察退出和清理结果，解释适用边界。

## 工程入口

- 当前练习：`exercises/managed-child-cleanup`
- 日志分析：`exercises/log-analyzer`
- 检查命令：`mise run check:learning`
```
