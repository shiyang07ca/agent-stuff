# 领域文档

工程 Skill 需要了解项目术语或已有架构决定时，按本文件查找资料。

## 开始探索前

按需读取：

- 根目录的 `CONTEXT.md`
- 如果存在根 `CONTEXT-MAP.md`，则根据其中的映射读取与任务相关的 `CONTEXT.md`
- `docs/adr/` 中与当前工作相关的架构决策
- 在多领域仓库中，还应检查 `src/<context>/docs/adr/`

如果这些文件不存在，直接继续，不报告缺失，也不预先建议创建。`discovery` 会在真正形成领域术语或架构决策时按需创建这些文件。

## 当前布局

本仓库使用单一领域布局：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-example-decision.md
│   └── 0002-another-decision.md
└── ...
```

如果以后拆成多个领域，则在根目录创建 `CONTEXT-MAP.md`，由它指向各子领域的 `CONTEXT.md`。

## 使用领域词汇

当任务标题、重构建议、假设或测试名称涉及领域概念时，应使用 `CONTEXT.md` 定义的术语，不要改用其中明确排除的同义词。

`CONTEXT.md` 只收录在本项目中有特定含义、会反复使用且容易混淆的概念。通用工程词、类名、配置键、命令和内部处理阶段留在代码或维护说明中，不要为它们另造一套中文名称。

如果需要的概念不在词汇表中，应先判断：

- 是否正在引入项目并不使用的新说法；如果是，优先改用项目已有说法
- 项目是否确实缺少这个术语；如果是，交由 `discovery` 补充

一个名称如果不能用一句普通话解释清楚，或者解释时还需要更多新造词，先简化名称，不要写入词汇表。

## 标记 ADR 冲突

如果建议与现有 ADR 冲突，必须明确指出，不能不作说明就覆盖，例如：

> 与 ADR-0007 的既有决策冲突，但值得重新讨论，因为……
