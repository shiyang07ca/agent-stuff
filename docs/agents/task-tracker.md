# 本地临时任务记录

需要在当前机器上暂存 PRD、任务拆分或交接信息时，写入 `.scratch/` 下的 Markdown 文件。该目录被 Git 忽略，不是项目长期记录；需要共享、审计或长期保留的内容移到 `docs/`、ADR 或项目约定的任务系统。

## 文件位置与正文

- 每项工作使用 `.scratch/<feature>/`，PRD 为 `PRD.md`。
- 每项任务一个文件：`tasks/<NN>-<slug>.md`；从 `01` 起编号，沿用已有编号，不覆盖任务。
- 标题下写 `Status:`、`Progress:` 和 `Blocked by:`，定义见 [任务状态](triage-labels.md)。
- 正文写清目标与必要范围边界、可观察的验收条件和检查方法。
- 有结果再添加 `## Answer`；讨论与交接按需追加到 `## Comments`，已有 `## 评论` 标题继续使用。

旧 `.scratch/<feature>/issues/` 和单字段状态由 `project-init` 按事实迁移；新旧目录同时存在或状态含义不明时保留原状并报告，不覆盖、猜测或机械替换。

## 选择与执行

1. 读取用户指定的任务；自动选择新任务时，只考虑 `Status: ready-for-agent`、`Progress: pending`、前置已满足且在当前授权范围内的任务。按用户顺序或业务优先级选择，条件相同时再按编号。
2. 续做 `in-progress` 任务先读交接记录，避免重复领取。开始时改为 `Progress: in-progress`；需要协作或交接时记录承担者和时间。
3. 完成时在 `## Answer` 写实际交付、验证结果和限制，再改为 `Progress: completed`，保留分诊角色。延后和取消不会自动解除下游依赖。
4. 中断时按需追加已完成、未完成与下一步，不维护重复进度表；在答复中说明状态变化。

没有用户授权时，不向外部任务系统发布、评论、关闭、删除或转派任务。不提交 `.scratch/`；完成不意味着需要删除记录。
