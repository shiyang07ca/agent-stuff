# 全局工程 Agent 约定

本文件只保存跨仓库长期适用的个人工程偏好。项目命令、目录结构、技术栈、业务规则和局部约定写在项目级 `AGENTS.md` 中。

先遵循当前任务目标和明确约束，再遵循适用的项目级规则，最后使用本文件中的默认偏好。

## 权限与范围

- 仅要求回答、解释、审查、诊断或规划时，读取必要材料并报告结果，不修改实现；若适用的 Skill 明确要求维护任务文档或状态，可以更新其约定的本地、可恢复文件，但不得修改项目实现，并在答复中说明。
- 要求修改、构建或修复时，直接完成任务范围内的本地、可恢复改动，并运行相关非破坏性检查。
- 外部或生产写入、推送、创建 PR、部署、对外消息、账户操作、删除不可重建数据、改写 Git 历史或明显扩大任务范围前，必须获得用户明确授权；已经授权时不重复确认。
- 只访问完成任务所需的敏感数据，不在日志、答复或提交中暴露敏感原值。
- 修改前检查现有状态并保留无关改动；无法安全合并时停止并说明冲突。

## 工作方式

- 先读取适用的项目说明和最少的相关代码、配置、测试或文档；信息不足时再扩大检查范围。
- 从任务目标、已知事实和必要约束出发，不把现有实现、历史习惯或未经验证的假设自动视为需求；现有方案已经满足目标时，不为理论纯粹性重构。
- 多个方案都能正确满足需求时，选择符合项目现有写法、假设更少、机制更直接的最小完整方案。新增抽象、扩展点、配置项、兼容层、依赖、文件或相邻重构，必须由当前需求或明确证据证明必要。
- 修复已确认的根因，不掩盖错误、不顺带处理无关问题，也不为假设中的未来需求预留能力。
- 优先在外部或不可信数据进入内部处理的边界进行校验；内部数据已有明确类型、接口约束或不变量保证时不重复校验，除非有证据表明这些保证不可靠。
- 保留错误原因和定位信息；只在恢复方式明确时重试、忽略或降级。
- 默认保持现有对外接口和行为；需要不兼容变更时，同步处理已知调用方和相关说明。
- 只有不同选择会实质改变正确性、安全、对外结果、数据处理、任务范围或不可恢复操作时才询问用户；其他情况采用影响最小、可恢复的合理判断继续。
- 明确的小任务直接执行；存在多个相互依赖步骤、较高风险或需要协调多处修改时，才使用带验证项的简短计划。

## 验证与收尾

- 修改后先运行最相关的检查；只有项目规则、失败结果或风险需要时，才扩大到完整测试、静态检查或构建。
- 改变可观察行为或修复缺陷时，如果现有测试不足以覆盖风险，按项目惯例补充最小必要测试；纯文档、文案、注释、元数据和机械性配置修改不新增单元测试，除非项目规则或实际风险要求。
- 达到用户要求并完成必要检查后停止。只报告实际完成和检查过的结果，明确说明失败、未验证、环境限制和未知事项；范围外问题仅在阻塞当前任务时处理。

## 版本控制

- 只有用户明确要求时才创建提交。
- 提交前检查工作区、暂存区和 diff，只提交本次任务产生的改动。
- 优先遵循项目提交规范；项目未规定时，使用中文 Conventional Commits 标题，例如 `feat(auth): 增加令牌刷新`。

## 资料与研究

- 对会变化、存在争议或影响技术决定的外部事实，优先核验当前一手来源，并区分已验证事实、基于证据的推断和未知信息。
- 需要长期保存、审计或重新计算的研究和数据结果，记录来源、日期、版本、输入和方法；普通事实查询不额外建档。

## 语言与术语

- 优先使用项目已有语言和术语。项目未规定时，中文用于沟通和维护文档；标识符、API、字段名、协议名、命令和错误码保持英文。
- 不为内部类、配置项、命令或处理阶段另造中文名称。若项目已使用 `CONTEXT.md`，只记录具有项目特定含义、会反复使用且容易混淆的术语；不要仅因本规则创建该文件。
